# 踩坑记录（现象 → 根因 → 规避）

格式：一行一条，`现象` → `根因` → `规避`。只记会复发、且下次不看就会再踩的。

## 自检脚本

- 自检里造 `restore_slot` 的桩，直接传 `{}` + 一个不存在的 slot 名 → 根因：`restore_slot` 先 `manifest.scan()` 找槽，找不到就 `return {"reason": "找不到 slot …"}`，**探测分支根本没跑到**，断言测了个寂寞 → 规避：桩必须造出真能被 `manifest.scan()` 认出来的槽（`<root>/<kind>/<slot>/manifest.json` + `manifest.parts[].zipPath` 指向真实存在的文件 + `target` 指向真实目录），并额外断言「目标目录一个字节都没动」。
- 断言名写成「删之前先写事件」，实现是「身份信息删前抄、事件删成功后落」→ 根因：把「留痕」理解成「先写后删」，没对齐代码顺序 → 规避：文案与断言名都要跟实现顺序一致，否则文档和代码互相打脸。

## 文档与实现

- README 里写 `<备份根>\state\ui-state.json` → 根因：按命名直觉写，没核 `engine`：:944 → 规避：凡文档里出现具体文件名/字段名，先在代码里 `Select-String` 核一遍，核完再写；自检里加一条「文档断言」防复发。
- `dshbackup\log.py` 留着一份 `human_bytes`（与 `sevenzip.human_bytes` 同功能不同舍入）→ 根因：只加注释说「界面用别处」，没查引用；实际零引用 → 规避：重复实现一律先查引用，**零引用就删**，并在模块 docstring 写明「本模块不提供格式化函数」。

## 断电/异常路径

- 兜底包索引 `idx.write_text()` 非原子 → 断电留半截 JSON → `json.loads` 抛错被 `except` 吃掉 → `rows = []` → 兜底包还在但不知道属于谁，回滚不了 → 规避：索引这类「小而关键」的状态文件统一走 `atomic_write_text`（tmp + `os.replace`）；读到坏文件要**改名留档 + 记事件**，不许静默降级成空列表。
