# UI 台账 · DSH 备份工具（M3）

> 依据：备份工具设计文档 §9 线框、架构决策记录第二版 §12/§14。
> 原则：先有能手工救命的包（M0），再有自动化（M1/M2），最后才是界面（M3）。本台账只描述 M3 的表面。

## 功能：一屏看清三个块备到哪了，并能立刻备一份 / 恢复一份 / 管住 DSH 环境

### 谁 / 何时 / 算完成

- **角色**：主人（单机单用户，非管理员启动是常态）。
- **触发**：想确认「我最近有没有备份 / 能不能退回昨天 / 我这台机器现在能不能直接重装」，或者刚装坏了一个插件想退回去。
- **完成判据**：看到「最远能退回几天前」这个数字，并在需要时点完一次备份或一次恢复且拿到可核对的结果（包在哪、旧状态在哪）。

### 涉及表面

| 表面 | 在哪 | 怎么进来 | 怎么出去（完成/返回） |
|---|---|---|---|
| S1 主屏 | `/` 单页 | 桌面快捷方式 → 起服务 → 自动开浏览器 | 关标签页即可，服务继续在后台跑 |
| S2 恢复确认弹层 | S1 内 overlay | 点 `[恢复…]` 或某份包行的 `[恢复这一份]` | `取消` / `Esc` 关闭；`开始恢复` 后转 S3 |
| S3 长操作进度条（页面顶部条） | S1 内，非独立页 | 备份或恢复一开始就出现 | 完成/失败后自动收起，留一条结果行 |

**表面数 = 3（含 1 个 overlay、1 个内联条），没有新页面、没有路由。** 配置与「怎么手工恢复」是 S1 的两个折叠块，不算独立表面。

### 状态矩阵

#### S1 主屏 · 总体

| 状态 | 界面说什么 | 用户能做什么 |
|---|---|---|
| 空（`backup_root` 里一份包都没有） | 灰字「还没有任何备份。第一次备份大约要 20–40 分钟，完成后会出现在下面。」+ 三个 `[立即备份]` 按钮高亮 | 点任一块的「立即备份」；或先去配置页核对路径 |
| 加载（首次 `GET /status` < 1s） | 表格骨架（三行灰条），不转圈 | 等；不阻断点击 |
| 加载（> 1s 或服务刚起） | 骨架 + 一行「正在读取备份目录…」 | 等 |
| 成功（有数据） | 三行表格：最新一份 / 份数 / 占用 / 覆盖到 | 立即备份、恢复、环境按钮、展开最近 8 份 |
| 部分成功（某层目录读不到） | 该行显示「读不到：<路径>（<errno 原因>）」，其它行正常 | 去配置页改路径；点「重试」 |
| 失败（服务连不上） | 全屏一行「连不上备份服务（127.0.0.1:8099）。服务可能没起来，双击桌面「DSH 备份」再试。」 | 重开快捷方式 |
| 无权限（`backup_root` 不可写） | 顶部红条「备份目录不可写：D:\…。改配置里的目录，或检查磁盘。」 | 去配置页 |
| 运行中（备份/恢复进行中） | 顶部进度条 + 「正在打包 基线…已处理 12,340 / 78,357 个文件，预计还要 8 分钟」 | 只能「停止」；停止后**已写完的包保留**，半份包自动清理（说清这句） |
| 已暂停（`paused=true`） | 顶部黄条「已暂停：不会自动备份，手动备份也会被拒绝。」 | 点「恢复运行」 |

#### S1 · 环境三个按钮（启动 / 重启 / 关闭）

| 状态 | 界面说什么 | 用户能做什么 |
|---|---|---|
| 端口通（网关在跑） | 「● 网关 3080 在跑」；`[启动环境]` 灰掉，`[重启环境]` `[关闭环境]` 亮 | 重启 / 关闭 |
| 端口不通 | 「○ 网关 3080 未启动」；`[启动环境]` 亮，另两个灰 | 启动 |
| 启动中（0–120s） | 「启动中… (n 秒)」按钮转灰 | 等；120s 超时转「失败」 |
| 失败 | 「启动命令失败：<末 3 行输出>」+ 提示「命令可在配置页改」 | 去配置页改命令 / 重试 |
| 命令缺占位符解析（`{dsh_pid}` 取不到） | 该按钮标 `不可用`，tooltip 写「当前 3080 端口没进程，取不到 PID」 | — |

#### S2 恢复确认弹层

| 状态 | 界面说什么 | 用户能做什么 |
|---|---|---|
| 未选包 | 下拉列出全部包（层 / 年龄 / 大小 / 校验状态），默认选最老的不可行 → 默认选**最新一份对话包** | 选一个 |
| 已选包，未开始 | 「将用 2026-10-25 04:00 的对话包覆盖 `.dsh\sessions` 与 `.dsh\attachments`。开始前会先给现在的内容打一份兜底包（永不自动删）。旧内容会改名成 `.pre-restore-<时间>`，不删。」 | `开始恢复` / `取消` |
| 兜底失败 | 红字「兜底包没打成（<原因>），已中止恢复。现在什么都没改。」 | 重试兜底 / 取消 |
| 校验失败（sha256 不符） | 红字「这个包已损坏（sha256 不匹配），换一份。」 | 选别的包 |
| 运行中 | 「正在解包到临时区…（已处理 n 个文件）」 | 不能取消（说明：中途取消会留半解压，需要手工清 tmp） |
| 完成 | 绿字「已恢复。刚才那份旧状态在 `D:\…\.pre-restore-20261025-1830`，要退回去就把它改回原名。」 | 关闭 |

### 文案

| 位置 | 文案 | 备注 |
|---|---|---|
| 表头三列 | 最新一份 / 份数 / 占用 / 覆盖到 | 「覆盖到」是最关键一列，不可省 |
| 档位标签 | `密集期` / `第 k 档 (lo–hi)` / `（这一档没有代表点）` | 灰字 |
| 待备 | `⚠ 待备` | 唯一形态，不弹窗 |
| 立即备份 | `立即备份` | 动词，不用「确定」 |
| 恢复 | `恢复…` / `开始恢复` / `取消` | 弹层里用「开始恢复」 |
| 停止 | `停止` | 附「已写完的包会保留」 |
| 暂停 | `暂停全部` / `恢复运行` | |
| 失败兜底 | 一句话原因 + 下一步 | 不用感叹号、不用「请稍候」 |

### 组件

- **复用**：无（新工程，零前端依赖，原生 `fetch` + 原生 DOM）。
- **新增**：`ui/index.html`（结构）、`ui/app.js`（状态机 + 轮询）、`ui/app.css`（一套克制的中性色）。共 3 个文件、0 个框架、0 个构建步骤。
- 新增组件数 3，未超预算（表面只有 3 个）。

### 验收

1. **功能验收（手动步骤）**：空态 → 点「立即备份（对话）」→ 运行中看到「已处理 n 个文件」→ 完成后表格出现 1 份 → 点「恢复…」→ 选它 → 看到兜底包提示 → 开始恢复 → 完成后核对 `.pre-restore-*` 存在。逐一复现上面每个状态各一次。
2. **交互验收**：主流程键盘可走完（Tab 到「立即备份」→ Enter 触发；Esc 关弹层）；不看帮助文档也能完成「备份 + 恢复」。
3. **数据验收**：成功与失败各留一条真实日志记录（`logs\backup-YYYYMMDD.log` 里 `archive_ok` / `archive_fail`），可 grep 核对。
